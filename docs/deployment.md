# PocketSolver deployment

The public demo at [www.nmokey.com/poker](https://www.nmokey.com/poker/) fills the
browser window. GitHub Pages serves the website iframe; Streamlit Community Cloud
runs the trained CPU model and live Groq comparison.

## Model selection

The default is **ModernBERT + linear**, the highest observed accuracy and lowest
log loss in the [completed development matrix](week2-results.md). Selectors offer
BERT Mini, MiniLM, DistilBERT and ModernBERT, each with a linear or MLP head.
Each of the eight combinations restores its independently fine-tuned encoder,
tokenizer and trained head from fold 1. Selection never attaches an untrained head.

The same 256 seeded multi-option examples are held out by all eight serving
checkpoints. The loader verifies encoder ID, head type, fold, protocol and hand
membership against the selected catalogue entry. Changing encoder/head preserves
a compatible hand, recomputes its trained-model result and reuses its Groq result
or in-flight Groq request. Benchmark results reset when the selection changes.

A process-wide store keeps one trained model resident across all sessions. Loading
and inference are serialized; the previous model is released before its replacement
loads. Downloads remain cached on disk. Selecting a model used by another visitor
can require a reload; the demo is intended for modest traffic on free CPU hosting.

## Saved results view

Choose **Results matrix** to compare all eight encoder/head combinations. Both
selectors stay visible and the current combination has a highlighted row and a
“Current” marker. This view reads saved files without downloading weights or
calling Groq. A direct link can use `?view=results`.

Accuracy and log loss come from the 10,000-example, five-fold development matrix.
Average latency comes from a separate local CPU benchmark, not Streamlit hosting;
see [measurement details](week2-results.md#serving-latency). The table offers a CSV
download. Its loader checks training protocols and serving-asset hashes, rejecting
mismatched checkpoint timings instead of displaying stale measurements.

- Existing Streamlit source branch: `codex/deploy-pocketsolver`. Keep it updated
  until the owner explicitly switches the app's source setting to `main`.

- Direct app: <https://nmokey-poker-decision-model-deploystreamlitapp-codexdepl-dhuhge.streamlit.app/>.
- Website: `nmokey/nmokey.github.io`, `docs/poker/index.html` and
  `docs/assets/css/poker.css`. The page uses `?embed=true` and a frame policy

The entrypoint directory has a separate `pyproject.toml`/`uv.lock` for CPU-only
PyTorch and serving extras. The root lock retains the training environment.

## Model release assets

`deploy/streamlit/assets.json` is a versioned serving catalogue with an explicit
default and independently checksum-pinned archive URL for every combination.
Release `meeting3-demo-models-2026-11-02-v2` contains eight archives, approximately
42–556 MB compressed each. Only the selected archive is downloaded on first use.
Each archive includes the weights, tokenizer, metadata, common hand sample and
per-file checksum manifest. Downloads/extraction have a 1 GiB per-archive bound,
safe-path checks and hash verification before loading.

Build a new release from existing trained artifacts and the prepared pool:

```sh
uv run --locked python scripts/package_demo_models.py \
  --root "$PWD" \
  --output "$PWD/artifacts/deployment/pocketsolver-models-v2" \
  --release meeting3-demo-models-2026-11-02-v2 \
  --config "$PWD/deploy/streamlit/assets.json"
```

The script requires exactly one fold-1 checkpoint per encoder/head, checks their
shared held-out membership and refuses to overwrite an existing staging directory.
For replacements, use a new output directory and release tag, upload all referenced
archives, and update the catalogue atomically with the application. Preserve the
old release for reproducibility. Never commit weights, source rows or credentials.
The earlier single-model v1 release remains historical; `scripts/package_demo.py`
is its legacy packager and is not used for the selectable catalogue.

## Secrets

The existing Groq key remains in Streamlit Secrets; model selection needs no new
key. At [share.streamlit.io](https://share.streamlit.io/), use the app's overflow
menu → Settings → Secrets to edit these values, or Advanced settings for a new app:

```toml
GROQ_API_KEY = "your-key"
GROQ_MODEL_ID = "openai/gpt-oss-20b"
POKER_LLM_DAILY_LIMIT = "100"
POKER_LLM_SESSION_LIMIT = "10"
POKER_LLM_COOLDOWN_SECONDS = "5"
```

Use ignored `.env`/`.streamlit/secrets.toml` files or environment variables locally.
If the app hostname changes, update the website iframe, generated frame policy
and documentation together. Verify the real app before publishing the website change.

Groq uses temperature 0, a 4,096-token completion limit, a 30-second network timeout
and no automatic retries. GPT-OSS uses low reasoning effort; hidden reasoning still
consumes completion tokens. Invalid replies and failures stay visible.

## Request limits and benchmark

SQLite reserves issued requests atomically: 100 shared and 10 per browser session
per UTC day by default, with a five-second cooldown and two concurrent provider
calls. Failed issued calls count too. New hand and Re-run engines request fresh
comparisons; unrelated reruns and encoder/head changes reuse the hand's LLM result.
A shared bounded worker pool and session-held futures prevent duplicate jobs on reruns.

The benchmark defaults to the selected trained model, with up to 50 hands. Live
Groq opt-in allows at most five and uses the same allowance. Quality metrics use
the common successful subset; response times use each engine's successful requests.
Model timing measures tokenization and inference after loading/warm-up; it does not
include model loading or waiting for another session's model operation.

These are per-instance traffic controls, not a provider spending guarantee. A host
rebuild can reset SQLite, and a new session can bypass its per-session cap. Model
predictions remain available after the live allowance is exhausted. Provider usage
and billing costs are not collected, and the small session benchmark is not exported
as a reproducible final study.

## Run locally

From the repository root:

```sh
uv sync --locked --project deploy/streamlit --no-dev
uv run --locked --project deploy/streamlit --no-dev streamlit run deploy/streamlit/app.py
```

Without local asset settings this downloads the selected release archive. If you
have already built the eight local asset directories, set `POKER_DEMO_ASSET_ROOT`
to their parent (for example `artifacts/deployment/pocketsolver-models-v2`, as an
absolute path). The legacy `POKER_DEMO_ASSET_DIR` accepts one verified asset directory
and only works for its matching encoder/head; it is not suitable for switching.

## Interpretation and validation

The aggregate 71.92% / 0.6078 ModernBERT linear result pools five folds over 10,000
examples. The demo serves one trained fold and 256 selected hands; its displayed
scores are not interchangeable with that aggregate or an independent final test.
All eight real checkpoints were exercised through the UI in the isolated CPU
environment, preserving the same hand and one mocked Groq call across all switches.
The benchmark and reset behavior passed. The measured peak for that local switching
smoke test was approximately 968 MiB; this is not a hosting resource guarantee.
Offline regressions cover wrong checkpoint labels, training/held-out membership,
eviction before loading, failed loads and concurrent session isolation.

## Relationship to opponent forecasting

The serving catalogue and live comparison use PokerBench Hero reference-action
checkpoints. Leduc forecasting and the real Hold’em history-feature models remain
research workflows. The latter reuse the neural architecture but predict observed
human actions; they are not deployed models or demonstrated better responses to
opponents. Adding an adaptive policy to the product requires appropriate response
targets or a payoff experiment. See the [results index](results/README.md),
[current project context](project-context.md) and [Hold’em study](meeting5-ablation-results.md).
